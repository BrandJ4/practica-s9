## Solución propuesta

### 1. Definition of Ready para testing
Antes de pasar una tarea a QA, el desarrollador debe proveer:
- Descripción de qué se implementó
- Casos de uso principales
- Casos edge conocidos
- Instrucciones de configuración/datos de prueba

### 2. Bug report estándar en GitHub Issues
Template para reportar bugs:
```markdown
## Descripción del bug
## Pasos para reproducir
1. ...
2. ...
## Comportamiento esperado
## Comportamiento actual
## Screenshots/logs
## Ambiente (OS, browser, versión)
```

### 3. Sesión de "Desk Check"
Antes de pasar a QA, el developer hace un walkthrough de 15 min con el tester mostrando la funcionalidad.

### 4. Canal dedicado dev-qa
Canal de comunicación exclusivo para dev↔qa con respuesta máxima de 1 hora.
