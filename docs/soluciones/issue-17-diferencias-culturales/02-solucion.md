## Solución propuesta

### 1. Idioma escrito como estándar
- Toda documentación técnica en un solo idioma (inglés o español, decidir uno)
- La comunicación escrita da tiempo para pensar y traducir
- Preferir GitHub Issues/PRs sobre reuniones verbales para decisiones importantes

### 2. Reuniones más inclusivas
- Enviar agenda con anticipación para que todos puedan prepararse
- Usar herramientas de traducción en tiempo real cuando sea necesario
- Crear espacio explícito para que todos hablen: "¿Alguien más quiere agregar algo?"
- Documentar decisiones por escrito después de la reunión

### 3. Glosario del proyecto
Crear `docs/GLOSSARY.md` con términos técnicos del proyecto en el idioma acordado:
```markdown
| Término | Definición | Equivalente |
|---------|-----------|-------------|
| Sprint | Ciclo de 2 semanas de desarrollo | Iteración |
| PR | Pull Request - solicitud de integración de código | - |
```

### 4. Cultura de respeto explícita
Documentar en el Team Agreement:
- No interrumpir cuando alguien busca palabras
- Confirmar entendimiento parafraseando: "Entiendo que quieres decir..."
- Feedback siempre sobre el trabajo, nunca sobre la persona
