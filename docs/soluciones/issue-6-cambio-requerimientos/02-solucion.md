## Solución propuesta

### 1. Gestión de cambios con Scrum
Los cambios mid-sprint no se implementan directamente. El proceso es:
1. Cliente solicita cambio → se crea Issue con etiqueta `change-request`
2. Product Owner evalúa impacto
3. Si es urgente: se negocia reducir alcance del sprint actual para acomodar el cambio
4. Si no es urgente: entra al backlog para el siguiente sprint

### 2. Documento de gestión de cambios
Crear `CHANGE_REQUESTS.md` en el repo que registre:
- Fecha de solicitud
- Descripción del cambio
- Impacto estimado (horas, tareas afectadas)
- Estado: Pendiente / Aprobado / Rechazado / Diferido

### 3. Comunicación con el cliente
Educar al cliente sobre el proceso Scrum y por qué los cambios mid-sprint son costosos.
